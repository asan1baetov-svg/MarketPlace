## 1. Что строим

Приложение курьера маркетплейса **Green Eco Mall** (Кыргызстан, KGS). Веб-приложение как PWA:
устанавливается на телефон, работает на ходу, одной рукой. Курьер получает предложения доставки,
забирает посылку у магазина, везёт покупателю, отмечает статусы и видит заработок.

Про доступ: роль `COURIER` бэкенд пока никому не выдаёт, права определяются наличием профиля
курьера. После входа запроси `GET /api/couriers/me`: профиль есть — показывай приложение;
`404`/`courier.courier_not_found` — экран «Стать курьером»; профиль есть, но
`moderationStatus = PENDING` — экран ожидания, `REJECTED` — причина отказа.

Язык — русский. **Только мобильный макет** (375–430px), десктоп — тот же макет по центру.

## 2. Стек

React 19 + TypeScript (strict) + Vite + PWA (`vite-plugin-pwa`, офлайн-оболочка), Tailwind 4,
Radix + свои компоненты, Redux Toolkit + RTK Query, react-router 7, date-fns (ru), lucide-react,
шрифт Geist Variable. MSW для моков (п.5).

## 3. Дизайн

Бренд общий: `--bg #F8F5F0`, `--surface #FFFFFF`, `--border #E5DDD0`, `--text #1A1A1A`,
`--text-muted #9B9589`, `--forest #1B2B20`, `--leaf #4A7C5E` (успех и активная доставка),
`--accent #E07840` (новое предложение, таймер), `--danger #B3401F`.

**Запрещено:** градиенты, «стекло», эмодзи, мелкий текст (меньше 14px), больше двух действий на
экране, модалки поверх модалок, анимации переходов.

**Нужно:**
- Одно главное действие на экране, кнопка внизу, высотой не меньше 52px, на всю ширину.
- Крупные цифры и адреса: адрес — 17–18px, подписи 13px. Курьер читает на улице, на солнце.
- Смена статуса — **свайп-кнопка** («Проведите, чтобы подтвердить») для необратимых шагов:
  «Забрал», «Доставил». Обычный тап — для «Принять» и «Отказаться».
- Предложение доставки показывай с таймером обратного отсчёта до `offerExpiresAt`; когда время
  вышло — сообщение «Предложение истекло», и элемент исчезает из списка.
- Звонки и навигация — системные ссылки: `tel:` для телефона, `https://2gis.kg/…` или
  `geo:`-ссылка для адреса. Своей карты не рисуй, её на бэкенде нет.
- Состояние сети: при ошибке запроса показывай плашку «Нет связи» и кнопку «Повторить»; действия
  не теряются — повтор того же запроса безопасен.
- Скелетоны, пустые состояния («Сейчас нет предложений»), тосты после действий.
- Деньги `250 сом` (значение API делить на 100), даты `dd.MM HH:mm`.

## 4. Экраны

1. **Стать курьером** (`/join`) — страна и город из справочника, зоны (необязательно), транспорт
   (пешком, велосипед, мотоцикл, авто — уходит свободным JSON в `vehicle`). Далее экран
   «Заявка на рассмотрении».
2. **Смена** (`/`) — главный экран:
   - Переключатель «На линии / Не на линии» (`ACTIVE` / `OFFLINE`) — пока не на линии,
     предложения не приходят.
   - **Новые предложения** (`bucket=new`): магазин, район, сумма заказа, таймер. Кнопки «Принять»
     и «Отказаться».
   - **Мои доставки** (`bucket=active`): текущие, с текущим шагом.
   - Карточка заработка за сегодня.
3. **Доставка** (`/deliveries/:suborderId`) — рабочий экран. Сверху шаги:
   Принял → Забрал → В пути → Доставил.
   - **Забрать:** название магазина, адрес, телефон (кнопки «Позвонить» и «Маршрут»), состав
     посылки (что и сколько). Кнопка «Забрал» активна, только когда `readyForPickup = true`
     (магазин собрал заказ), иначе подпись «Магазин ещё собирает».
   - **Везти:** адрес клиента и комментарий из `dropoff.address` (произвольный JSON: улица, дом,
     квартира, подъезд, этаж, телефон, комментарий — показывай понятным списком, телефон кнопкой),
     сумма заказа.
   - Действия: «Забрал» (`/pickup`), «В пути» (`/in-transit`), «Доставил» (`/deliver`),
     «Не удалось» (`/fail` с обязательной причиной из списка + свой текст).
4. **История** (`/history`) — завершённые доставки (`bucket=done`) с датой и результатом.
5. **Заработок** (`/earnings`) — сумма за период (по умолчанию 30 дней), список начислений по
   доставкам, баланс кошелька и кнопка «Вывести» (заявку подтверждает админ, перевод пока ручной).
6. **Профиль** (`/profile`) — город, зоны, рейтинг, статус модерации, уведомления, выход.

**Чего на бэкенде нет — не рисуй:** карты с маршрутом и треком, чата с клиентом или магазином,
фото подтверждения доставки, смен и графика работы, выбора нескольких доставок «пачкой»,
автоматических выплат курьеру.

## 5. Технические требования

- `VITE_API_URL` + `/api`, `Bearer`-токен, refresh с ротацией и общей очередью; `auth.refresh_reused`
  или 401 на refresh — выход.
- Списки: `?page=0&size=20`, ответ `{ content, page, size, totalElements, totalPages }`.
- Обновление данных: активный экран «Смена» — опрос `bucket=new` и `bucket=active` каждые 15 секунд
  (только когда вкладка видима); экран доставки — каждые 20 секунд, чтобы поймать
  `readyForPickup = true`. Push-уведомлений пока нет.
- **Бэкенд не развёрнут** — MSW-моки (`src/mocks/`) строго по контракту п.6: профиль курьера,
  2 предложения с таймером (одно истекает через 60 секунд), 1 активная доставка, проходящая все
  шаги, 8 доставок в истории, заработок и кошелёк. Переключатель `VITE_USE_MOCKS`.
- Ошибки — `application/problem+json` с `code`: `courier.courier_not_found` (нет профиля),
  `courier.courier_not_approved` (ещё не одобрили), `courier.job_forbidden` (доставку уже забрал
  другой курьер — обнови список), `courier.job_status_invalid` (статус уже изменился),
  `courier.job_not_ready_for_pickup` (магазин ещё не собрал), `courier.order_unavailable`
  (детали заказа временно недоступны — покажи, что есть, и кнопку «Повторить»).

## 6. Контракт API (всё под `/api`, с токеном курьера)

### Профиль и смена
| Метод и путь | |
|---|---|
| `POST /couriers` | `{ countryId, cityId, zoneIds?: [], vehicle?: {…} }` → `{ id }` |
| `GET /couriers/me` | `Courier` |
| `POST /couriers/me/status` | `{ status: "ACTIVE"\|"BUSY"\|"OFFLINE" }` → 204 |
| `GET /catalog/geo/countries` · `GET /catalog/geo/cities?countryId=` | справочники для формы |

`Courier = { id, userId, countryId, cityId, zoneIds, status, moderationStatus:
"PENDING"|"APPROVED"|"REJECTED", rejectionReason, rating }`.

### Доставки
| Метод и путь | |
|---|---|
| `GET /couriers/me/assignments?bucket=new\|active\|done&page=` | страница `Delivery` (без параметра — все) |
| `GET /assignments/{suborderId}` | `DeliveryDetails` — карточка с адресами и составом |
| `POST /assignments/{suborderId}/accept` · `/reject` | 204 |
| `POST /assignments/{suborderId}/pickup` · `/in-transit` · `/deliver` | 204 |
| `POST /assignments/{suborderId}/fail` | `{ reason }` → 204 |

`Delivery = { suborderId, orderId, shopId, cityId, status, courierId, offerExpiresAt,
readyForPickup, failureReason, acceptedAt, deliveredAt }`.
Статусы доставки: `CREATED` (заказ ещё не оплачен), `AWAITING_COURIER`, `OFFERED` (предложено вам,
ждёт ответа до `offerExpiresAt`), `ACCEPTED`, `PICKED_UP`, `IN_TRANSIT`, `DELIVERED`, `FAILED`,
`NO_COURIER`, `CANCELLED`.

`DeliveryDetails = { delivery: Delivery, pickup: { shopName, address, phone } | null,
dropoff: { address: {…JSON адреса клиента}, amountMinor, currency, orderStatus,
items: [{ name, qty }] } }`.
`pickup` может быть `null`, если catalog временно недоступен — покажи остальное и предложи повторить.

### Деньги
| Метод и путь | |
|---|---|
| `GET /couriers/me/earnings?from=&to=` | `{ courierId, from, to, totalMinor, items: [{ suborderId, amountMinor, currency, createdAt }] }` (по умолчанию 30 дней) |
| `GET /wallet` | `[Wallet]` — кошелёк курьера |
| `GET /wallet/{walletId}/transactions?page=` | проводки |
| `GET /wallet/{walletId}/payouts?page=` | заявки на вывод |
| `POST /wallet/payouts` | `{ walletId, amountMinor, bankDetails: {…} }` → заявка (подтверждает админ) |

`Wallet = { id, ownerType, ownerRef, currency, balanceMinor, heldMinor, availableMinor }`
(`ownerRef` курьера = его `courierId`). Автовыплат курьерам пока нет: вывод только заявкой.

### Уведомления
`GET /notifications?page=`, `GET /notifications/preferences`, `PUT /notifications/preferences`
`{ channels: { PUSH, SMS, TELEGRAM } }`.

## 7. Приёмка

- Страница `/ui` с компонентами: свайп-кнопка, карточка предложения с таймером, шаги доставки,
  строка адреса с кнопками звонка и маршрута, пустые состояния, плашка «Нет связи».
- На моках проходит полный путь: стать курьером → выйти на линию → принять предложение →
  дождаться готовности магазина → забрать → в пути → доставить → увидеть начисление в заработке;
  отдельно — отказ от предложения и «Не удалось» с причиной.
- Скриншоты экранов «Смена» и «Доставка» (шаги «Забрать» и «Везти») — на согласование до остального.
